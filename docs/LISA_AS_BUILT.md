# LISA As Built

The running record of decisions and deviations made while building the LISA engine. Every place where the code departs from the spec, resolves a silence in the spec by following Hummel's code, or constructs a mechanism that no witness fully specifies gets an entry here. Entries are dated. One paragraph per line.

The spec is `lisa/LISA_SPEC.md` in the Box research folder. The claims audit beside it, `LISA_CLAIMS_AUDIT.md`, is the list of claims these decisions bear on. Line numbers below refer to Hummel's `Vers1.00/` files.

## Phase 0 (2026-09-22)

- **Random stream location.** The shared random stream lives at `src/models/random.ts` rather than the spec's `src/sim/random.ts`, because this repo's engines live under `models/`.

## Phase 1: engine core (2026-09-22)

### Configuration space, as built

- **Switches added to spec §8.7.** Four differences between the code and the 2003 paper needed a switch the spec did not list: `outOfPropositionRule` (`maxSecondMax`, the code's, or `summed2003`, A9); `refreshScope` (`allAnalogs`: the code's `init_all_inputs` applies the global-inhibitor refresh to every analog including the driver, or `nonDriver`, the paper's §4.3); `modeResetsToNeutral` (A1.1 says "neutral otherwise"; the code keeps the previous mode); and `hypothesisNormalization` (see the Table 2 finding below). Three numbers were also added so the paper preset can express itself: `opToOpInhib` (within-class weight for predicates and objects, absent in the code), `spInhibitionGain` (the code's "implicit wt of -2" on SP-to-SP inhibition; the paper's gain is the sensitivity alone), and `mappingExcitationGain` (the factor 3 of A10, hard-coded in both).
- **Switch dropped.** `activationRule` is gone: γ, δ and τ are numbers, and the paper presets set τ = 1 with the paper's γ and δ, which makes the code's update identical to Eq. 5 and 1997's A15.
- **Switch options renamed.** The 2003 recipient rule (A8) is a normalized sum, not max/second-max, so `recipientWithinClassInhibition` is `code` | `normalizedSum2003` | `divisive1997`, and `driverLateralRule` is `maxSecondMax` | `normalizedSum2003` (A2). Under `normalizedSum2003` the driver has no lateral inhibition among P, predicate or object units, since A4 and A5 have none.
- **`normalizedSum2003` class membership (ours, from A8's prose).** Parent-mode and neutral P units inhibit one another; child-mode P units inhibit one another and objects; SPs, predicates and objects each within class. The normalizing count uses the units of the class above `inhibitorThreshold` (the paper's Θ^I, which it uses for both purposes).
- **`weber2003` top-down normalization.** A12 divides the SP-to-predicate/object input by 1 + the number of SPs above. That is applied only under `semanticInputRule = weber2003`; under `cosine` the code's plain sum stands.
- **Grouped batching (ours).** `batchedSPOrder = grouped` runs a multi-proposition phase set as consecutive sub-phases, one proposition's SPs at a time, each for `iterationsPerSP × (its SP count)` iterations. Mapping hypotheses, retrieval flags and connections persist across sub-phases; `topDownOK` is computed over the active sub-phase's SPs only. There is no separate between-proposition reset signal: the global inhibitor turns on by itself when no SP is above threshold at the switch. This is one reading of Hummel's July 2007 note; the spec's claim tests will show whether it matters.
- **`ignoreArgSemanticsWhenBatched` (ours, from 2003 p. 232).** When a phase set holds more than one proposition, the driver's objects send nothing to the object semantics. Recipient objects then get input only from their SPs and from mapping connections.

### Ported from the code, with notes

- **Iteration order** follows `runLISA.update_network` exactly: initialize inputs, recipient P-unit modes, driver inputs, recipient and dormant inputs, activations (driver, then each recipient with retrieval, then dormant), semantics, hypotheses.
- **`times_fired` is not a firing count.** In `dataTypes.SPUnit.update_inhibitor` the counter increments on every iteration in which the inhibitor is in its fast-growth phase while the excitor is still above threshold, so it reads 10 or 15 after three firings. The code only ever tests it against 1. The run record keeps it as `timesFired` and adds `firings`, counted as rising edges of activation through 0.5, which is what the tests use.
- **The driver is refreshed too.** Under `refreshScope = allAnalogs`, driver P, predicate and object units start each iteration at `td = GI` like everything else; only the phase-set SPs have their `td` overwritten with the attention input. Parent-mode driver P units are spared once `topDownOK` when `parentPropsSkipRefresh` is on. This is what the code does and differs from the paper's "nondriver analogs".
- **Global inhibitor at phase-set start.** The code carries the previous phase set's last value into the first iteration; it has no effect there (all activations are 0), so the engine resets it to 0.
- **Which connections retrieval creates** (`hebbs.create_hebbs`). A recipient P unit that crosses threshold on its own gets connections to the phase-set's top-level propositions whatever its mode; if it is in parent mode its SPs connect to the phase-set SPs, its predicates to the phase-set predicates, its objects to the phase-set objects, and its child propositions to the phase-set's child propositions. A recipient child proposition therefore connects to the driver's child propositions only when retrieved through its parent. Copied as is.
- **Connections are symmetric and stored once.** Hummel stores each with the recipient unit first. The engine stores `(lower id, higher id)`; every rule that needs a row or column filters a unit's connection list by the other end's analog, which is what his per-target "hebb sets" did.
- **Inconsistent (row-and-column) lists follow the code's retrieved-endpoint rule.** `find_inconsistent_hebbs` walks only the hebb sets of retrieved units, so a connection with one unretrieved endpoint sees only half its cross. The published update then normalizes every connection, retrieved or not, exactly as the code does.
- **Hypotheses accumulate on any connection whose two ends are both retrieved**, including a connection between two current recipients that was created when one of them was the driver. `update_hebb_buffers` does not check analog roles. Copied; a scenario with two recipients that were mapped to each other earlier will show it.
- **Vers142 consistency is computed from the topology**, not by comparing every pair (spec §8.3 item 6), with the code's doubled entries: an SP connection counts twice for its P connection (parent or child link), and a predicate or object connection counts twice for its SP connection. Sibling SP connections count once and must share no endpoint.
- **Vers142 settling** uses the code's constants (excitation 3, inhibition 20 from round 20, γ 0.8, δ 0.1, τ 0.1, stop at 0.001 change or 500 rounds). They are named constants in `mapping.ts`, not configuration.
- **Object out-of-proposition rule.** The code tests `max_sp.child_prop` where it means `second_max_sp.child_prop` (spec §8.3 item 2); the engine tests the intended SP.
- **Attention** is applied on the fly to the priority when selecting a proposition, never written back (spec §8.3 item 3).
- **Cosine rule guard.** The zero-length guard is in the cosine computation, not on the stored weight length (spec §8.3 item 4).
- **Retrieval** is one pass over the recipient's P units per iteration (spec §8.3 item 5).
- **Unlimited WM** is ported from `god_like_update_driver_inputs` as is, including its hard-coded inputs (−10 to the finishing SP's predicate and argument, −100 and −10 for the global inhibitor).
- **Scenario `Parameters` blocks.** `DriverInhibition` also scales both sensitivity bounds, as `build.read_parameters` does (the interactive menu uses a different formula; the file form is the one scenarios use). `BailUponSettling`, `WithinGroupSupport` and the similarity switches are recognized and ignored with a warning.
- **Self-supervised learning is not implemented yet** (phase 3). A scenario with `SSL_ON` or `SSL_OK` runs its mapping and reports a warning. Mapping quality is still computed at the end of each `SSL_OK` phase set, so the Mapping tab can show it.
- **Not implemented until phase 5**, and refused with an error at construction: `driverRule = hh1997`, `mappingAlgorithm = hh1997`, `recipientWithinClassInhibition = divisive1997`, `recipientPInput = maxSinceSelection`, `semanticInputRule = fanInNormalized1997`, `dormantCompetition = network`. The `HH1997` preset therefore does not run yet; its settings exist so the completeness test covers it.

### Findings

- **Table 2 comes out differently under the paper's own appendix rule.** Page 233 says that after the hypotheses of Table 2 are normalized and the weights updated, "Mary→Tom takes a positive mapping weight and the remainder of the object mapping weights remain at 0". That is what happens if every hypothesis is divided by the largest hypothesis anywhere (2). Under the rule the same paper states on p. 256, and that Hummel's `original_update_hebb_weights` implements, each hypothesis is divided by the largest in its own row and column, and then Bill→Sally, Mary→Tom and Sam→Cathy all come out at 0.495 while every wrong pairing goes to 0: one update finds the whole object mapping. The engine has a switch, `hypothesisNormalization` (`rowColumn` | `global`), and `engine.test.ts` asserts both outcomes. This belongs in the claims audit as a tier 3 item under audit item 1, since it changes how much work the two-proposition phase set has to do.
- **Hummel's code fails the love triangle with the published mapping rule.** Through the reference harness, his own "H&H 03 Parameter Suite" (published rule, η = 0.9) mapped the structural love triangle wrongly in 10 of 10 runs (P1↔P2 swapped, Bill→Chad), while his default suite (Vers142) solved it in 19 of 20 (run 16 produced the proposition-swapped mapping Amy→Chad, Bill→Abe, Cat→Beth, so his `lovetri9.bat` 10/10 was a favorable sample). Our engine reproduces both: 20 of 20 correct under `Hummel2007` with final weights identical to his to three decimals (P 0.990, SP 0.993, predicate and object 0.968), and 0 of 10 correct under `HummelSuite03`. `reference.test.ts` compares the rates with a 10-point tolerance. Audit item 1's first test is therefore already answered on the code side; what the paper-side settings (`ignoreArgSemanticsWhenBatched`, `batchedSPOrder`) do is the phase 2 Claims-tab comparison.
- **The `Hummel2015` defaults do not change the love triangle**: 10 of 10 correct with the same weights, in both engines.
- **Airport/beach, mapping only.** Without inference, both his code and ours map the target's P3 `want(Joan, P2)` to the source's P5 `cause(P3, P4)` at 0.880 rather than to P3. When the source is the driver, P5's SP fires with the source's P3 as its child argument; the target's P3 is that child's mapping, so it activates in child mode while the driver's P5 is active, and the P5–P3 hypothesis grows with nothing in the P5 row to compete. With inference on, his code infers a target unit for P5, which takes that row, and P3→P3 wins at 0.982 (his `4.bat` shows the same). The phase 3 acceptance test should assert P3→P3 with inference on.
- **Hummel's `4.bat` is odd.** Of its four runs, three print empty mapping lists (every weight at or below 0). The spec already says not to treat that file as a target.
- **Top-down timing agrees.** Top-down input is first released at a mean of 316 iterations in his code and 319 in ours over the love triangle's phase sets (range 235–475 versus 236–498), driven by the same inhibitor dynamics. Vers142 settled in a mean of 45 rounds in his runs and 40 in ours; two of his ten first-phase-set settlings took over 100 rounds, none of ours did. Not investigated further.
- **Time-sharing capacity** (Hummel2007, 5 seeds each, one proposition with n roles): see the `[time-sharing capacity]` line printed by `engine.test.ts`. Recorded, not asserted.

### Reference harness

- `reference/pylisa/` is a `fissix` conversion of Hummel's six model modules to Python 3, with a stub for his pygame graphics, a headless driver (`harness.py`) and a summarizer (`analyze.py`). Two lines of his code are patched, both marked `HARNESS`: the settling routine records its round count, and a `str.pop` call that would crash on a `Note:` line inside an analog is removed. `reference/expected/*.json` are its outputs; `reference.test.ts` compares distributions.
